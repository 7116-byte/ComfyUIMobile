# 第一次连接 ComfyUI Mobile

App 是遥控你自己的 ComfyUI 工作站的 Android 客户端。它不在手机运行模型，不提供显卡、模型下载或云平台账号。请先让同一个工作流在电脑网页里正常生成。

## 先选连接方式

| 你的情况 | 用什么地址 | 准备事项 |
| --- | --- | --- |
| 手机和电脑接同一路由器 | `http://电脑的局域网IP:端口` | 开启监听，放行防火墙端口；避免访客 Wi-Fi 的设备隔离 |
| 手机不在家，已配置互通 VPN | `http://电脑的VPN地址:端口` | VPN 已连通，路由与访问策略允许该端口；无需依赖局域网扫描 |
| 云 GPU / 远程整机 | 平台提供的完整 ComfyUI HTTP 根地址 | 确认满足下方兼容条件，不是应用分享页或单个 API |

推荐先从同一 Wi-Fi 开始。App 不创建 VPN、不配置隧道、不代开服务器端口。

## 在电脑上开启局域网监听

监听地址表示“服务器接受哪些网卡的连接”。ComfyUI 命令行默认监听本机；`--listen 0.0.0.0` 开启 IPv4 网卡监听，默认端口为 8188。依据：[ComfyUI 官方启动参数](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy/cli_args.py)。以下操作由工作站所有者在自己的电脑完成。

### 启动器 / 整合包

1. 打开启动器的 **设置 / 高级设置 / 启动参数**。
2. 找“局域网访问”“允许远程访问”“监听地址”之类选项；若有监听地址，填 `0.0.0.0`。
3. 若没有专门选项，但支持“额外启动参数”，添加 `--listen 0.0.0.0`。已有 `--listen` 参数时修改原值，避免重复填写。
4. 记下实际监听端口，保存并重启 ComfyUI。
5. 查看启动器控制台，确认服务启动成功。

不同启动器、版本的选项名称不同，上面是通用配置方法，不承诺固定菜单路径。官方 Desktop 请使用对应版本的实例 / 启动设置；如果不能设置监听，可先采用便携版或手动启动。**这里需要开启本机服务访问，不需要点击“生成分享链接”。**

### 官方 Windows 便携版（.bat）

1. 在便携版目录复制原来的启动 `.bat`，留作备份。
2. 用文本编辑器打开实际使用的文件，例如 NVIDIA 版的 `run_nvidia_gpu.bat`。
3. 在运行 `ComfyUI\main.py` 的那一行末尾追加 `--listen 0.0.0.0`，保留原有显卡、性能等参数；不要加到 `pause` 行。
4. 保存后停止原进程，再用修改后的文件启动。

典型 NVIDIA 便携版示例，具体仍以你的原脚本为准：

```bat
.\python_embeded\python.exe -s ComfyUI\main.py --windows-standalone-build --listen 0.0.0.0
pause
```

目录和启动文件说明见 [ComfyUI 官方便携版文档](https://docs.comfy.org/installation/comfyui_portable_windows)。

### Python 手动部署

使用原有虚拟环境，在 ComfyUI 目录启动：

```shell
python main.py --listen 0.0.0.0 --port 8188
```

如果你已有启动命令，只追加或修改监听参数，保留其他需要的选项。已使用不同端口时，无需改回 8188，手机填写相同端口即可。

## 找到应该填写的地址

Windows 在终端运行 `ipconfig`，找到当前联网的 Wi-Fi / 以太网网卡的 **IPv4 地址**。例如地址是 `192.168.1.20`、端口是 `8188`，手机填：

```text
http://192.168.1.20:8188
```

- `0.0.0.0` 是监听配置，不是手机要连接的目标。
- `127.0.0.1` / `localhost` 在手机上指向手机自己，不是你的电脑。
- 使用实际端口。省略端口时，当前 App 默认补 `8188`；云平台使用 80 等端口时必须显式填写。
- 不要复制启动器的设置页、平台控制台地址或 `/prompt` 等单个接口。
- 局域网扫描只帮助发现当前网段的默认 8188 服务；自定义端口、跨网段和 VPN 请手动输入。

先在**手机浏览器**打开同一地址。打不开时先解决网络或服务监听，再回 App 连接。

## 防火墙与远程访问

下面以 **Windows 10 / 11、家庭可信局域网、TCP 8188** 为例。其他端口请替换为实际值，不要为排错关闭整个防火墙，也无需设置路由器公网端口映射。

### 1. 确认电脑的网络类型

打开 **设置 → 网络和 Internet**，进入当前连接的 Wi-Fi / 以太网属性，在网络配置文件类型中选择 **专用网络**。不同 Windows 版本的页面位置略有差别；前提是你信任该网络及其中的设备。公共场所或公司受管网络不要随意改成专用。

仅创建“专用”规则、但电脑当前使用“公用”网络时，规则不会对该连接生效。操作依据：[微软网络类型说明](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/essential-network-settings-and-tasks-in-windows)。

### 2. 如果启动时弹出防火墙询问

确认弹窗中的程序确实是当前 ComfyUI 环境使用的 Python / 服务进程，再允许它访问可信的专用网络。不要误把浏览器、启动器界面程序的授权当成 ComfyUI 后端已经放行。程序路径随整合包、虚拟环境或更新而变化时，旧的程序规则可能不再适用。

已有可用规则则不必重复创建。没有弹窗或仍被拦截，可以按下面建立端口规则。

### 3. 手动建立入站端口规则

需要电脑管理员权限：

1. 按 **Win + R**，输入 `wf.msc`，回车；或搜索“高级安全 Windows Defender 防火墙”。
2. 左侧选 **入站规则**，右侧点 **新建规则**。
3. 规则类型选 **端口**，下一步。
4. 选 **TCP → 特定本地端口**，填写 `8188`，下一步。只填 ComfyUI 实际端口，不选所有端口。
5. 选 **允许连接**，下一步。
6. 家庭局域网仅勾选 **专用**，下一步。
7. 命名为 `ComfyUI 8188（可信局域网）`，完成。
8. 在入站列表找到新规则，打开 **属性 → 作用域**，将远程 IP 限制为手机 IP 或可信局域网网段。例如电脑为 `192.168.1.20`、手机同属 `192.168.1.x` 时，可按实际子网填写 `192.168.1.0/24`；不要照抄不属于你的网段。

规则建好后保持 ComfyUI 运行，使用手机浏览器打开 `http://电脑IP:8188`。能打开后再进入 App。微软规则配置说明同时涵盖协议、端口、网络配置文件和 IP 作用域：[官方防火墙规则文档](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure)。

### 4. 仍打不开时

- 核对规则已启用、实际端口一致，当前网络类型与勾选范围一致，远程 IP 作用域包含手机。
- 手机和电脑需互相可达，访客 Wi-Fi 或路由器的 AP 隔离可能阻止访问。
- 使用 VPN 时，电脑看到的来源可能是 VPN 地址，网络类型也可能不同；按实际 VPN 地址与策略单独配置，不能只套家庭局域网规则，更不要为了省事开放所有公网来源。
- 第三方防火墙或公司组策略也可能拦截，Windows 规则不一定能覆盖；受管设备请联系管理员。
- 如果此前明确拒绝过对应 Python 程序，检查现有阻止规则；不要批量删除其他规则。停止使用时可禁用或删除自己新建的 ComfyUI 规则。

不要直接把无认证的 ComfyUI 端口暴露到公网。远程使用建议先建立可信 VPN，再按 VPN 内可达地址连接。App 不提供访问鉴权或服务器安全加固。

## 云平台给的纯链接能用吗？

**取决于链接背后是什么，不取决于它是否叫“ComfyUI”。**

当前客户端只支持 `http://主机:端口` 根地址，尚不支持 HTTPS、路径前缀代理、带查询令牌或用户名密码的链接，也不支持平台账号登录、Cookie 或 API Key 认证。不要把平台给的 `https://` 强行改成 `http://`。

| 平台给你的东西 | 当前结论 |
| --- | --- |
| 完整 ComfyUI 独立实例的 HTTP 根地址，无平台登录拦截 | 可能兼容，仍需实际验证接口及前端版本 |
| HTTPS 临时分享域名或 HTTPS 代理地址 | 当前不支持 |
| 打开后先登录平台、输入访问口令、带 `?token=...` | 当前不支持；浏览器登录不会自动同步给原生网络请求 |
| `http://host:port/comfy/` 等路径前缀代理 | 当前不支持，App 会明确提示，不会静默丢掉路径再连接 |
| 工作流应用分享页、Serverless、只提供生成 API 的服务 | 不等于完整 ComfyUI 服务，当前不能直接接入 |
| 菜单里的“导出 API”“部署到 Comfy API”或 Comfy Cloud API | 属于另一类工作流运行 / 云 API 入口，当前 App 未实现对应认证与协议适配 |

完整实例还需满足：

- 可加载原始 ComfyUI 前端及其自定义节点脚本，而非仅有平台自己的简化网页。
- 标准信息和节点接口可访问，例如 `/system_stats`、`/object_info`。
- 标准工作流 userdata 接口可读写、上传接口可用、`/prompt` 可提交任务、结果接口可读取文件。
- `/ws` WebSocket 可连接，代理不会拦截长连接；节点、模型与工作流相匹配。

这些是由当前客户端实现推导出的必要条件，不代表任意平台已经验收。官方云 API 自己有独立认证要求，见 [官方 Cloud API 说明](https://docs.comfy.org/development/cloud/overview)。后续支持 HTTPS 和平台认证需要单独适配，不能只放开一个地址判断。

## 按失败位置排查

| 现象 | 优先检查 |
| --- | --- |
| 手机浏览器也打不开 | 服务是否运行、监听地址、电脑 IP、实际端口、防火墙、访客网络隔离、VPN 路由 |
| 扫描不到，但手动地址能打开 | 扫描仅覆盖当前网段默认端口；直接手动输入即可 |
| App 提示只支持 HTTP / 不支持路径或令牌 | 链接类型超出当前兼容范围，不是手机安装失败 |
| 能读服务器信息，但打开网页或初始化前端失败 | 原始前端、自定义节点脚本、代理重定向、服务器版本兼容性 |
| 工作流为空 | 电脑端是否已保存工作流、userdata 路径和权限是否正常 |
| 节点 / 模型选项失效 | 电脑端补齐节点、模型或重新选择有效选项；不要反复点击生成 |
| 有队列但没有实时节点进度 | 是否为 App 提交的任务、WebSocket 是否可达；其他客户端任务有服务端进度限制 |

仍有问题时，在设置中导出诊断日志，先移除私人地址、令牌、提示词与作品信息，再附上 App / ComfyUI / 前端版本和复现步骤 [提交 Issue](https://github.com/7116-byte/ComfyUIMobile/issues/new/choose)。请勿提交签名密钥、整份工作流或平台登录凭据。
