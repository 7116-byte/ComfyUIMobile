# 原图分段下载

手动保存到相册、后台自动下载和远程文件分享共用 `ComfyClient` → `OriginalFileDownloader`。
整个过程只读写原文件字节，不解码、不缩放、不重新压缩图片或视频。不需要修改服务器、VPN、反向隧道或代理配置。

## 策略

- 先发 `Range: bytes=0-0`，不依赖 `HEAD` 或不可靠的 `Accept-Ranges` 声明。
- 服务器直接返回 `200` 时，复用这次响应完成普通下载，不再重复请求整个文件。
- 收到有效 `206`，且文件至少 **8 MiB**、具有有效强 ETag，才启用分段。
- **8–32 MiB 用 2 路，超过 32–48 MiB 用 3 路，超过 48 MiB 用 4 路**。每个文件最多四路；不同下载任务的临时文件相互隔离。
- 每段发送 `If-Range`，强制 `Accept-Encoding: identity`；拒绝混合压缩后的范围。
- 每段必须返回精确的 `Content-Range` 起止值及总大小、相同强 ETag、相同最终 URL，声明长度和实际字节数也必须一致。
- 所有分段成功后按连续范围合并，重算各段 SHA-256 并和收到时的摘要比较，最后检查合并长度。
- 不支持 Range、没有强 ETag、弱 ETag、版本改变、范围不正确或分段传输失败：取消并等待其他分段结束，丢弃临时分段，再尝试一次普通完整下载。完整下载失败则报错，不把残缺文件当作成功。
- 普通下载要求 `200`、无 `Content-Range`，按 Content-Length（如提供）及 HTTP 消息分帧验证完成。没有可校验的总长度时不并行。

ETag 用于版本一致性，不等于服务器的 SHA-256。这里的 SHA-256 用来检测临时分段与合并过程的本地字节变化；服务器没有提供可信全文件摘要时，不能声称已完成服务器端到端密码学认证。HTTP 本身也不提供 HTTPS 的传输认证。

协议依据：[RFC 9110 的 Range 与 If-Range 语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)。

## 取消、失败和存储

- 协程取消会立即取消所有在途 HTTP 调用，包括等待响应头或卡在读取中的连接；取消不会触发普通下载回退或后台重试。
- 验证完毕前不向 MediaStore 输出；最终写入发生取消/失败时，调用方删除未完成的媒体条目。批量保存不会吞掉取消后继续下一张。
- 自动下载先完成暂存，再在 App 内部存储上原子移动到目标文件，随后写入缓存索引；不会直接覆盖目标为半个文件。分享使用同一文件接口。
- `cacheDir/original-downloads/transfer-<UUID>` 在成功、失败及取消后清理。若进程被强杀，下次启动下载时清除前一进程遗留的暂存目录。
- 临时目录和自动保存目录必须位于支持原子移动的同一文件系统；App 的 `cacheDir/filesDir` 满足此用途。不支持原子移动时明确失败，不降级为直接写入可见目标。
- 为保证完整后再保存，需要临时磁盘空间，分段/合并阶段峰值约为原文件两倍；相册最终写入期间也会短暂同时存在暂存和目标文件。
- 不是跨进程断点续传；中断后重试会重新下载。

## 验证

`OriginalFileDownloaderTest` 使用真实本地 TCP HTTP 服务，覆盖 2/3/4 路并发、字节一致、200 复用、Range 拒绝/畸形范围/错误长度/截断、文件版本变化、缺失版本、chunked、普通下载失败、阻塞连接取消、合并后输出取消、原子发布、并行任务隔离、孤儿临时文件清理，以及两个公开下载入口。

```powershell
.\gradlew.bat testDebugUnitTest assembleRelease --offline --no-daemon
```

可选只读集成测试：将当前进程环境变量 `COMFY_DOWNLOAD_TEST_URL` 指向现有的 ComfyUI `/view` 原文件链接，再执行上述测试。`OriginalFileDownloadIntegrationTest` 比较普通 GET 与 2/4 路下载的全文件 SHA-256，不创建生成任务。未指定该变量时只跳过这一个集成测试。

是否更快取决于单连接限速、链路带宽、服务器并发能力和手机磁盘性能；不承诺固定倍数。本机回环吞吐数据不能代表手机经 VPN 的实际速度。
