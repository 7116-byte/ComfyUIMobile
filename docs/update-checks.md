# 更新检查与限流

2026-10-31 在用户手机上确认正式版为 0.1.69。手机网络请求 GitHub 最新 Release API 返回限流错误，两个 API 镜像均为 HTTP 403；同一手机访问官方 `releases/latest` 页面可跳转到 v0.1.71，APK 的 HEAD 请求和 SHA-256 下载均成功。手机已安装包的签名证书与原正式签名一致。

0.1.69 至 0.1.71 的检查代码将所有请求失败转为 `null`，调用方因此可能提示“已是最新版本”，并记录检查时间。这不能证明没有新版本，也不能说明发布附件不可下载。

v0.1.72 的修正：

- API 不可用时请求官方最新正式发布页，校验跳转仍指向本仓库及合法正式版本标签。
- 找到新版本后检查对应 SHA-256 文件及 APK 是否可访问，再显示更新入口。真正下载时继续校验完整文件哈希、包名、版本及签名。
- 所有来源都失败时报告检查失败，避免误报最新或把失败记录为成功检查；协程取消继续正常传播。
- 不向 App 嵌入 GitHub 登录令牌。

v0.1.72 本地一键验收共 182 项 JVM 测试，181 通过、1 项原有可选网络测试跳过；桥接回归、正式构建、lintVitalRelease 和原签名校验通过。之后已在用户手机覆盖安装正式版，原有 539 项作品和 6 条保存规则保留；用户手动检查更新时反馈等待时间较长。

v0.1.73 将 API、镜像与官方发布页并发检查，首个有效结果返回后取消其余请求；整体检查限时 12 秒。更新页显示检查中状态、防止重复点击，并保留结果。新增有效“无更新”结果可提前结束和失败传播回归。下载、哈希与 APK 身份校验要求保持不变。详细本次验收见 [版本说明](releases/v0.1.73.md)。

旧版无法通过远端 Release 改写自身检查代码。当前可从 [v0.1.72 Release](https://github.com/7116-byte/ComfyUIMobile/releases/tag/v0.1.72) 下载原签名正式包覆盖安装。v0.1.71 本身仍使用旧检查逻辑。
